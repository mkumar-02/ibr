# Glossary

| Term | Meaning |
|---|---|
| **Assistance unit** | Entity that benefits from a programme: person, family, or household (CD.COM.13) |
| **Beneficiary** | Person or group that has received a benefit from at least one programme; root IBR subject |
| **Benefit** | A specific transfer or service received (cash, voucher, in-kind, training, …) |
| **DCI** | Digital Convergence Initiative — social protection interoperability standards ([spdci.org](https://spdci.org)) |
| **Enrolment** | Relationship of a beneficiary to a programme, with status and dates |
| **G2P Bridge** | OpenG2P service that executes disbursement envelopes; downstream of PBMS |
| **IBR** | Integrated Beneficiary Registry — this product |
| **Manifestation** | Deployable registry product built on Registry Gen2 (e.g. NSR, Farmer; IBR only if Decision 0 = A/A′) |
| **B+** | Architecture option: standalone IBR service as SoR, consumed read-only by FR/NSR/DR |
| **SoR** | System of record — authoritative store for a given fact type |
| **NSR** | National Social Registry — OpenG2P social registry manifestation |
| **PBMS** | Programme & Beneficiary Management System — OpenG2P SP-MIS |
| **Programme** | A social protection scheme with a stable code and implementing institution |
| **PRS.IBR.\*** | DCI process identifiers for IBR ↔ SP-MIS use cases |
| **Registry Gen2** | OpenG2P Registry platform (`registry-platform`) |
| **Social Registry (SR)** | Registry of potentially eligible people/households (not limited to those who received benefits) |
| **SP-MIS** | Social Protection Management Information System — programme operations system (PBMS is OpenG2P’s) |
| **UIN** | Unique identity number / foundational ID used to join systems |
| **WebSub** | Publish-subscribe mechanism used for async DCI `on-search` and event notification |
